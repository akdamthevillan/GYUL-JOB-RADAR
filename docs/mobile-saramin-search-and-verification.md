# 사람인 모바일 검색·지원 상태 검증 프로토콜

> 목적: **검색 색인의 문구와 실제 모바일 페이지의 접수 버튼을 구분**해, 마감된 공고를 지원 가능한 공고로 오판하지 않는다.
> 사람인 공식 API 키 없음. 접근제한 우회, 로그인 회피, 무단 대량 크롤링/스크래핑 금지.

## 1. 공고 검색 (발굴)

1. 허용된 브라우저에서 `https://m.saramin.co.kr/`의 채용정보 검색 화면을 연다.
2. **지역 필터**를 부산 전체로 선택한다. 김해와 양산은 별도 지역 검색으로 모두 조사한다.
3. `data/search-config.json > search_strategy`의 키워드를 **한 개씩 별도 검색**한다. 예: `마케팅`, `마켓팅`, `MD`, `디자인`, `기획`, `일러스트`, `포토샵`; 다른 확장어도 순회한다.
4. 가능하면 최신순으로 정렬한다. 지역별·키워드별 어느 범위를 확인했는지 기록한다. 회사 산업/경력연수로 사전 누락시키지 않는다.
5. 공고별 원문 URL의 `rec_idx`(사람인 공고번호)만을 키로 중복 처리한다. 이미 마감 이력이 있는 번호는 재등록하지 않는다.
6. 검색결과가 많거나 브라우저 접근이 불가능하면 **검색 완전성은 보장할 수 없다고 명시**한다. 구글/Bing 검색 색인은 보조 후보 발견용이지 모바일 검색 전체의 대체가 아니다.

## 2. 모바일 원문 버튼 확인 (판정)

한 공고의 모바일 원문(`https://m.saramin.co.kr/job-search/view?rec_idx=...`)을 연다. **같은 rec_idx**인지 확인한다.

| 직접 본 화면 상태 | 데이터 상태 | 처리 |
| --- | --- | --- |
| 하단 빨간색 **입사지원** 활성 버튼 + 상단 마감 안내 없음 | `verified_open` | 같은 날의 화면 확인 방식과 근거 기록 |
| 하단 **접수마감** 비활성 버튼 또는 **본 채용정보는 마감되었습니다** | `closed_postings` | ID와 마감 버튼 관찰 근거 기록, 목록 제거 |
| 검색결과만 있고 모바일 버튼을 확인하지 못함 | `recently_listed` 또는 `재확인 필요` | 신규 후보로만 취급; 지원 가능이라고 단정하지 않음 |
| 지원방법이 자사 사이트/이메일/전화/방문 | `재확인 필요` | 사람인 버튼이 없다는 이유만으로 마감 판정 불가. 실제 외부 지원방법 별도 확인 |
| 접속 차단, 로그인 필요, 로딩 실패, 동적 버튼 미노출 | `재확인 필요` | 페이지 미확인 상태로 남기고 마감으로 간주하지 않음 |

**마감 예정일만 남아 있어도 모집이 조기에 종료될 수 있음**. 반대로 마감일이 없는 `채용 시 마감` 공고는 매번 버튼 확인이 필요하다.

## 3. GitHub Issue로 보낼 증거 필드

`[GYUL-IMPORT]` Issue는 공개된다. 개인 신상정보 및 실제 스크린샷에 포함된 개인 정보를 공개 저장소에 업로드하지 않는다.

직접 버튼을 본 `verified_open` 후보는 모두 다음 필드를 포함해야 한다.

- `application_button_state: "apply_enabled"`
- `application_evidence_kind: "user_screenshot"` 또는 `"browser_visual"`
- `application_checked_at: "YYYY-MM-DD"` (검증 당일, 한국시간)
- `verified_at: "YYYY-MM-DD"` (검증 당일), `verification_evidence`(관찰한 문구와 버튼), `verified_source_url`(동일 공고번호의 모바일 URL)

위 정보가 없으면 자동 등록기는 `verified_open` 주장을 받아들이지 않고 `재확인 필요`로 처리한다. 이 필드는 **관찰 과정의 자기 신고 데이터**로, 프로그램만으로 실제 스크린샷이 존재함을 입증하지는 않는다.

접수 마감을 확인한 공고는 `closed_postings`로 제출하고 `id`, `reason`(접수마감 포함), `closed_confirmed`, `evidence_url`과 함께 다음을 명시한다.

- `application_button_state: "closed"`
- `application_evidence_kind: "user_screenshot"` 또는 `"browser_visual"`
- `application_checked_at` = `closed_confirmed` (YYYY-MM-DD)

지원 버튼 미확인 상태에서 과거 마감일만 보고 **확정 마감** 이력을 수동 추가하지 않는다. 코드의 날짜 경과 자동 정리 정책은 별도로 유지한다.

## 4. 정합성·주기

- `verified_open`은 오늘 확인한 화면만 유효하다. 다음 날 재확인 전에는 접수 여부 미확인으로 전환된다.
- `recently_listed`는 최신 검색 근거와 미래 또는 당일 마감일이 있는 경우에만 최근 공고 노출 상태다. 실제 지원 버튼과는 별개다.
- `rec_idx`가 다른 동일 회사·동일 제목 공고는 각각 유지한다. 반대로 회사 채용목록의 다른 번호가 마감됐다는 이유로 현재 번호를 삭제하지 않는다.
- 자사 홈페이지나 외부 지원방법은 독립적으로 접근/확인해야 한다.
- 채용공고 탐색/버튼 확인은 **실제로 브라우저에 접속 가능한 담당자 또는 허용된 브라우저 실행 환경**에서 한다. 현재 GitHub Actions는 외부 사이트를 수집하지 않으며, API 키가 없다고 대량 자동 스크래핑을 추가하지 않는다.
- 매번 보고할 것: 실제 검색한 지역과 키워드, 실제 열어본 개별 원문 수, 활성·마감·불명 각각의 수, 신규 공고 수, GitHub 반영 및 Pages 배포 결과.

## 5. 이번 문제의 검증 예시

- `rec_idx=55251835`: 2026-10-21 사용자 스크린샷에서 **입사지원** 버튼 활성 및 10/23 마감 관찰 → `verified_open`.
- `rec_idx=55166027`: 2026-10-21 사용자 스크린샷에서 **본 채용정보는 마감되었습니다** 및 **접수마감** 비활성 버튼 관찰 → 마감 이력 등록, 목록 제외.

각각의 스크린샷은 공개 저장소에 복사하지 않고, 해당 공고의 공개 URL과 확인 일자 및 화면 관찰 문구만 기록한다.
